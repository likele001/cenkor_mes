lightmes（SaaS） × cenkormes（独立版）功能对比清单

版本定位核查 交付边界参考 初版 2026-08-21 复核 2026-10-08 复核 2026-10-22 复核 2026-10-26

用于区分「lightmes 全集」与「cenkormes 独立版 + 扩展」两条产品线的能力边界。2026-10-26 复核按实际代码重写：纠正旧的 community/pro 分包说法，把独立版能力拆成「核心内置 / 需装扩展 / 真缺口」三态，并补入 2026-10 新增的 8 项能力落点。

核查对象：lightmes（SaaS + 单厂同栈）　×　cenkormes（独立版）
核查方式：实际 Model / API 路由 / 页面 / 迁移 / 扩展 manifest.json 比对，非关键词表象

一、版本定位（2026-10 已变更，旧说法作废）

版本定位许可 / 分发结构
lightmes 全集：多租户 SaaS 平台 + 完整业务模块；同一套代码也支持单厂独立部署 2026-10-16 起转私有闭源商业分发 单仓单线，不再有 community/ + pro/ 分包；旧文档的「AGPL 公开 + 私有 overlay」已过时
cenkormes 独立版：单租户私有部署，薄核心 + 运行时扩展宿主 + 应用中心 AGPL-3.0 开源 独立仓库，不含 SaaS 平台层（租户/套餐/订阅/计费）

结论：两者不是「开源版 vs 商业版」的简单二分，而是「全集闭源」与「薄核心开源 + 商业扩展」两种商品形态。对比时必须以「装了什么扩展」为口径，否则会把扩展能力误判成核心能力或缺项。

七、扩展插拔闭环（2026-10-22 全量交付）

判据：安装失败是否影响存量、更新是否可回滚、卸载是否留残渣。三项全绿才算「闭环」，只做到「装上能用」是半开环。

八、结论与建议

  • 核心制造闭环（计划/工单/报工/质量/库存/采购/外协/追溯/考勤）两边都内置，是共同地基，不存在「开源版被砍」。
  • 「独立版没有」多数是「没装扩展」：CRM UI、ERP 财务、往来核对、安全库存、设备点检、盘点、计时工资、临时报表、审批、ABAC 都在扩展目录里。对外交付必须把扩展授权与安装流程一起给，否则客户看到的是空壳。
  • 真正的独立版缺口只有 5 项：客户询价 RFQ、多级 BOM、送货单打印、按发货对账、报工即时预估工资。前两项影响销售与计划链，优先迁核心。
  • lightmes 的护城河已不是「AI 存在与否」，而是 AI 计量/钱包/一体化套件 + SaaS 平台层。独立版已有 7 个 AI 扩展补齐大部分场景，差异在计费与深度整合。
  • 独立版独有价值要主动讲：可插拔扩展、外部 CRM 适配、追溯树、单租户一键部署、AGPL。这些是 lightmes 没有的卖点，不要只拿 lightmes 的能力表反向要求独立版。
  • 本页更新节奏：每批扩展或核心能力上线后同步一次；旧结论（community/pro 分包、748/539 API、32/3 AI 模块、10 个扩展 zip）已作废。
