核查方式：服务端实际 Model / API 路由 / services/ai 模块比对（非关键词表象）

四、落地上建议

  • 核心制造闭环（计划/工单/报工/质量/库存/采购/财务/CRM/考勤/追溯）在独立版已完整，开源主干无需砍除。
  • 报价 CPQ / 模具 / SPC：旧文档标注的“有表无功能”已过时——报价在 crm.py 已实现，模具/SPC 已作为独立付费扩展交付。
  • AI 能力层 + 排查诊断层 是 cenkormes 与 lightmes 的最大真实缺口（cenkormes 仅 3 个占位 stub，lightmes 有 32 个 AI 服务模块）。因依赖外部 LLM key/向量库且为核心差异化，建议做成需自备 key 的付费扩展 / Pro 门控，不进开源主干。
  • 落地优先级：① 先做 production_diagnosis（规则+统计的异常排查预警扩展，纯复用核心数据、只读、可真实回测，不依赖 LLM）；② 再做 ai_assistant（对话+RAG，用户自备 OpenAI 兼容 key，复用已有 chroma）；③ 行业模板包；④ workflow/ERP 属地基走核心补全或门控。
  • 推进节奏：A 线（纯扩展、仓库外开发打包、零风险）持续产出可售 zip；B 线（require_pro 门控 reports / exec_dashboard）收编高价值核心功能；C 线由 hub 侧完成上传→审核→定价→购买→安装。
