一、产品形态（与上版一致，数字更新）

版本定位许可 / 分发结构
lightmes v2.15.1 全集：多租户 SaaS 平台 + 完整业务模块，同一套代码也可单厂独立部署 私有闭源商业分发 单仓单线（无 community/pro 分包）；SaaS 平台层、订阅计费、AI 钱包都在核心内

八、结论与建议

  • 规模差距在缩小，但仍约 2 倍：管理端页面 99 vs 233、H5 29 vs 40、核心端点 436 vs 878、核心代码 6.8 万 vs 13.6 万行。计入已装扩展的 513 个端点后，独立版业务面覆盖已接近全集，差在 SaaS 平台层与深度。
  • 「独立版没有」现在基本等价于「扩展没装/没授权」：上一版的 CRM、ERP 财务、往来核对、库存三件套、点检、计时工资、审批、ABAC 等已全部装上（授权 active）。但当前仍有 12 个已授权未安装，客户看到的就是没有；交付 SOP 应把「扩展授权 + 安装 + 健康检查」写进验收单，而不是只交主程序。
  • 真正的核心缺口只剩 4 项：多级 BOM、送货单打印、按发货对账、报工即时预估工资。前两项影响计划与发货交付，建议优先迁核心；RFQ 已用扩展补齐，可作为「缺口 → 扩展」的样板。
  • 7 个扩展的源码缺口已补（erp_bridge/oee/project/rfq/subcontract_plus/subcontract_print/trace_graph）：已从实例目录回收进 mes-extensions，补齐 README 十节后 pack.py --check 全绿并重新打包，源码已提交。与 hub 的 uploads/apps 逐个比对确认运行时文件逐字节一致（zip 整体 SHA 不同只因 README 与时间戳），无需重发同名版本。
  • lightmes 的护城河已转向「SaaS 平台层 + 计费 + 项目经营」，而不是单个 AI 功能。cenkormes 的 AI 能力数量已够，差在钱包计费与一体化深度；这条差距不应靠继续加 AI 扩展来追。
  • 独立版的卖点要主动讲：可插拔扩展、扩展分发闭环、外部 CRM 适配、单租户一键部署、AGPL。这些是 lightmes 结构上没有的，不要只用 lightmes 的能力表反向要求独立版。
