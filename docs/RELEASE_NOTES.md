## v2.2.1 — 2026-11-05
本版重点是「在线升级」的可靠性。11-02 任务 #7 是升级功能上线后第一次真实执行，失败在 disk full，暴露出三个会让升级/回滚卡死的缺陷，本版全部修掉。

在线升级（高危修复）：
1) 僵尸任务同时锁死升级与回滚：进程在备份/构建/迁移阶段被中断时任务永久停在 running，而创建升级与回滚都有 active 拦截，只能登库改状态。现按「不在本进程执行集合 + 锁持有者已退出 + 阶段超时」三重判据自动收尸；判据刻意保守——在跑的不杀、锁被存活进程持有的不杀、pending 给 300 秒宽限、backup 阶段给 90 分钟以免误杀大库 mysqldump。另加 force-fail 接口供紧急人工解锁。
2) 依赖安装失败仍标记成功：pip 非 0 只写一行警告就继续，任务可能显示 success 但进程起不来。现改为失败后用 pip --dry-run 复核，环境已满足则放行并写明理由，仍不满足则中止；同时把依赖/构建/迁移/换入统一纳入回退保护，避免「磁盘是新代码、进程是旧代码、依赖还缺着」的错位。
3) 前端换入失败导致线上 dist 消失：两次 rename 之间失败时 dist 已不存在且未记入回退列表，站点直接 404。现失败即把 dist.__bak 还原，还原也失败则明确提示手动 mv。

在线升级（其它）：
- 开工前磁盘体检，可用空间不足 2GiB 直接拒绝，把「跑到一半才炸」提前成「根本不开工」
- 守护脚本要重启的 celery/beat 单元支持 CENKORMES_CELERY_UNITS 配置，避免同机多实例时升级预发连带重启生产 worker
- 升级失败自动回滚代码（git checkout -f 回到起点）并回退已换入的前端产物
- /api/health 执行 SELECT 1，数据库不可用时返回 503

发版链路：
- 新增版本一致性闸门：tag / VERSION / CHANGELOG.json 三者必须一致，否则发布工作流在 preflight 阶段直接失败。此前打了 tag 忘补 CHANGELOG 时 Release 会退化成空壳，只有翻 GitHub 才发现
- 回填历史 tag 缺失的 Release（8 个 tag 此前只有 4 个，含生产版 v2.2.0）
- scripts/release-all.sh 在打 tag 前先过校验，本地发版同样被拦住

安全与账实加固（9 项）：
- 报价转订单真实生成订单与明细（含折扣折算单价），校验状态/客户/明细，重复调用幂等返回
- 对账单核销加行锁并在锁内校验余额，防并发超收
- 附件读取收紧为上传者本人、超级管理员或具 attachment.view 权限者；删除失败不再静默吞异常
- 审批留痕按 biz_type 映射业务权限，未带类型时只返回有权类型的数据
- 飞书回调配置 Encrypt Key 后强制加密报文、配置 Verification Token 后校验 token
- 非 dev 环境仅在设置 ADMIN_INIT_PASSWORD 且达到最小长度时创建默认管理员

其它：
- 修正扩展路由冲突误判与无路由扩展加载
- 新增独立版官网落地页 standalone.mes.cenkor.cn；修移动端表格首列折行与长命令断行

升级说明：本版无新增数据库迁移，升级后需重启后端，关于页版本号才会更新。

## v2.2.2 — 2026-11-05
本版把「在线升级」从 git 通道彻底换成发布产物包，客户机从此不需要 git、不需要 SSH key、更不需要装 node。

在线升级（通道重构）：
1) 客户机不再依赖源码仓库。此前升级走 git ls-remote / fetch / checkout，客户机必须能拉到仓库（私有仓库要 SSH key），前端还得在服务器上 npm ci && build；现在改为从 GitHub Release 下载产物包 cenkormes-vX.Y.Z.tar.gz，校验 SHA256 后逐文件覆盖。包内已带 CI 构建好的 dist，这一步彻底消失。
2) 产物包由 CI 自动产出。tag 推送后 package job 构建两个前端 → git archive 只取被跟踪的文件 → 灌入 dist → 二次删除 .env 与 backend/data 并用 find 断言兜底 → 检查 VERSION/main.py/requirements.txt 三样齐全 → 打 tar.gz + sha256 挂到 Release。Source code 快照不含 dist，不能直接部署。
3) 覆盖安装只写包内存在的文件，永不覆盖 backend/.env、backend/data/、node_modules/、.git/、虚拟环境与 logs/；前端 dist 整体原子换入并保留 dist.__bak。上游已删除的文件按 .release-manifest.txt 的「旧清单 − 新清单」精确清理，首次以产物包升级时因无清单一份都不删——宁可留垃圾，不删客户文件。
4) 校验缺失即拒绝安装。Release 既无 digest 也无 .sha256 时报错中止，不再有「装了再说」的路径；确需安装必须显式设 CENKORMES_ALLOW_UNVERIFIED=1。

发版链路加固：
- 新增 preflight 闸门：tag / VERSION / CHANGELOG.json 三者必须一致，不一致就在建 Release 之前失败。此前打了 tag 忘补说明，Release 正文会退化成空壳，只有翻 GitHub 才发现。
- 闸门用两个独立 checkout：校验脚本从主干取，--root 指向目标 tag。回填历史版本时旧 tag 里可能没有脚本，直接 checkout 过去会 exit 127——校验逻辑不能放在被检查对象里。
- attach 单独成 job 并显式 --repo。Release 创建是秒级、前端构建是分钟级，合并会让窗口期内点「立即升级」拿到「该版本没有产物包」；该 job 没 checkout，gh 无法从 .git 推断仓库，必须显式指定。

文档：
- 新增 docs/RELEASE_PROCESS.md：维护者发版 SOP、CI 四道 job 职责、产物包规格与保护清单、客户机两条升级通道、回滚与排错手册（含全部真实踩坑）。
- docs/DEPLOYMENT.md 第 8 章改为产物包通道，明确「Source code 快照不含 dist，不能直接部署」。

升级说明：本版无新增数据库迁移。客户机可用后台「立即升级」或 scripts/upgrade.sh 升级到本版；从本版起，后续每个版本都能靠这套通道自我升级。
