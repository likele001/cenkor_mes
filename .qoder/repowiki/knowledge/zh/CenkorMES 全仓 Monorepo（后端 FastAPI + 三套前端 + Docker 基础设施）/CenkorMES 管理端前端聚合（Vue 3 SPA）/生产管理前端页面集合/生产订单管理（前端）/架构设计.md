模块由一个主路由页面 `OrdersPage.vue` 与一个独立导入页 `OrderImportPage.vue` 组成，并在 `orders/` 子目录下提供可复用的 `OrderCreateDialog.vue` / `OrderDetailDialog.vue` / `OrderEditDialog.vue` 三个弹窗组件。

- 入口：`OrdersPage.vue` 通过 `AdminPage` + `AdminDataTable` 渲染订单列表，使用 `productionApi.listOrders` 分页加载，并内嵌 detail/create/edit 三个 `el-dialog`；`OrderImportPage.vue` 通过 `router.push('/production/orders/import')` 从列表跳转进入。
- API 边界：所有后端调用集中在 `@/api/production`（`listOrders` / `createOrder` / `updateOrder` / `confirmOrder` / `rejectOrder` / `getOrder` / `fetchOrderFormOptions` / `exportOrders` / `importOrdersExcel` / `downloadOrderImportTemplate`），不直接访问 axios。
- 业务状态机：订单状态为 `draft → pending_confirm → confirmed → producing`，在模板中通过 `statusTagType` / `statusLabel`（来自 `@/utils/status-maps`）统一渲染，按钮按当前状态禁用/启用（如仅 `pending_confirm` 显示驳回，仅 `draft/pending_confirm` 可审核）。
- 行级锁定：已确认/生产中订单的 SKU 行带 `locked` / `lock_reason`，编辑时根据 `order_plan_locked` 与行锁决定字段是否禁用，体现“计划下发后不可改型号”的约束。
- 编号生成：新建订单时调用 `systemApi.nextCode('order')` 获取 `ORD+日期+序号` 建议号，提交前经 `codeForSubmit` 清洗。
- 依赖方向：页面 → `@/api/production` / `@/api/system` → 后端 FastAPI；UI 复用 `@/components/admin/*`、`@/utils/display`、`@/utils/code`、`@/utils/status-maps`、`@/utils/automationFeedback`。
