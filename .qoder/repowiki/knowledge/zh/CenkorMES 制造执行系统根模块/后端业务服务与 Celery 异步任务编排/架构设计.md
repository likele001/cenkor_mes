本模块以 `backend/app/celery_app.py` 为唯一入口：创建名为 `cenkormes` 的 Celery 实例，从 `app.core.config.settings` 读取 broker/result/timezone 配置，并通过 `celery.autodiscover_tasks(["app"])` 自动发现 `app.tasks` 下的所有任务；Beat 定时表硬编码了薪资日/月计算与生产自动化流水线扫描，同时 `DEFAULT_CRON_JOBS` 列表被 `services/cron_job_seeder.py` 与 `/admin/cron-jobs/defaults` 接口复用，实现代码与数据库双源同步。

子模块按职责分层协作：
- `services/feishu/` 提供飞书 Open API 客户端、OAuth、事件回调与卡片交互，被 `tasks/notify.py` 与 `services/notification_pipeline/` 调用作为消息通道之一。
- `services/notification_pipeline/`（含 `notify_dispatcher.py`、`ws_hub.py`）将事件路由到飞书/企微/钉钉/站内信，并把大屏刷新事件写入 WebSocket 连接池。
- `services/production_automation.py`、`services/planning_optimizer.py`、`services/dispatch_candidates.py` 构成「自动建单 → 排产优化 → 自动派工」流水线，由 `tasks/production.py` 中的 `automation.pipeline` 定时触发。
- `services/order_import.py`、`services/sku_batch.py`、`services/reporting_and_labels.py` 等纯同步服务供 API 层直接调用。
- `tasks/` 下仅暴露 Celery task 装饰器函数，内部委托对应 `services/` 中的领域逻辑，保持同步/异步解耦。

跨子模块共享依赖集中在 `shared_services`（`notify_dispatcher`、`ws_hub`、`fe.client`、`company_settings`、`entity_refs`），子模块不直接耦合 Redis/Celery，而是通过该共享层接入。
