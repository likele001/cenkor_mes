本模块由三个并列子目录组成，均依赖 `app.core` 与 `app.models`，但不被业务代码反向引用：
- `alembic/`：Alembic 迁移引擎。`env.py` 从 `app.core.config.settings.DB_URL` 注入连接，使用 `app.models.Base.metadata` 作为目标元数据；`versions/0001_init_schema.py` 通过 `Base.metadata.create_all(checkfirst=True)` 一次性建表，后续 `0002~0004` 增量迁移（MRP 分包、物料领料仓库入库、ERP 模块）在 `upgrade()` 中直接调用 `op.add_column` / `create_table` 等 alembic 操作。
- `scripts/`：独立可执行的 CLI 工具，每个文件对应一个数据初始化场景（`demo_data.py`、`seed_demo.py`、`seed_crm_dictionaries.py`、`seed_print_templates.py`、`seed_sofa_materials.py`、`repair_*` 修复脚本、`import_scanwork_ref.py` 等）。统一通过 `sys.path.insert(0, os.path.join(os.path.dirname(__file__), ".."))` 把 `backend/` 加入导入路径，再经 `app.core.db.SessionLocal` 获取真实 MySQL 会话，按幂等策略（`get_or_create` 或先查后插）写入基础主数据与演示订单/工单/报工/工资闭环。
- `tests/`：pytest 测试集。`conftest.py` 用 `sqlite:///:memory:` 创建全量模型表（动态 `pkgutil.iter_modules(app.models)` 注册所有子模块），并通过 `PRAGMA foreign_keys=ON` 开启外键约束；每个测试函数以事务级 session fixture 运行并在结束后 rollback。测试覆盖安全、验证码、自动编码、核心报工→审核→算薪流程、产能计划、门户访问、生产自动化、存储等，断言主要落在 `app.crud.*` 层而非 FastAPI 路由层。
