模块按职责划分为六个子目录，依赖方向自下而上：
- `api/request.ts` 基于 uni.request 封装 `ApiResp<T>` 统一响应体，集中处理 Bearer Token、401 跳转登录、超时提示；导出 `apiGet/apiPost/apiPut/apiDel/apiPostQuery` 及 `getToken/setToken/clearToken`。
- `api/admin/` 与 `api/h5/` 分别面向管理端与员工端业务接口，每个文件对应后端一个路由域（production/master/warehouse/purchase/finance/system 等），并通过 `admin/index.ts` 聚合为 `adminApi` 命名空间；`crudHttp.ts` 在 request 之上再封装 CRUD 五件套，自动适配 `{ items }` 分页结构。
- `stores/auth.ts` 使用 Pinia 维护 token、用户信息、未读消息数，并暴露 `hasPermission`；`stores/app.ts` 仅维护全局 loading。
- `composables/useAdminCrudPage.ts` 是核心复用层：根据 `types/adminCrud.ts` 的 `CrudSchema` + `constants/adminCrudSchemas.ts` 中的 schema 注册表，自动生成列表、搜索、新增/编辑表单、删除、refList 下拉选项加载等完整后台页面逻辑。
- `composables/usePermission.ts` 作为权限门面，包装 `authStore.hasPermission` 并提供 `requirePermission/requireEmployee` 带拦截跳转的守卫。
- `constants/permissions.ts` 集中声明与后端 seed.py 对齐的 PermissionCode 枚举；`constants/adminMenu.ts` 以数据驱动方式定义管理端分组菜单、快捷入口与审计入口，并通过 `useAdminMenu()` 做权限过滤。
- `locales/` 基于 vue-i18n 配置 zh-CN/en-US/ko-KR，默认语言从 `uni.getSystemInfoSync().language` 推导并持久化到 `LOCALE_STORAGE_KEY`。
- `utils/` 提供纯函数工具（格式化工具、导航、媒体选择、任务展示、状态标签、自动化反馈、订阅等），不持有状态，被各层自由引用。
